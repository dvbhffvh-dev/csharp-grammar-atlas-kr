# 01. 프로그램의 구조와 첫 실행

[이전: 전체 학습 안내](../../README.md) · [다음: 02 변수와 자료형](../02-VariablesTypes/README.md) · [전체 목차](../../README.md)

## 시작 전에

프로그래밍 경험이 없어도 시작할 수 있습니다. 저장소 안내에 따라 .NET 10 SDK와 Visual Studio에서 솔루션을 여는 방법을 먼저 확인하세요.

이 단원은 C# 14 / .NET 10 프로젝트에서 실행합니다.
명령은 저장소 최상위 폴더에서 실행하세요.
Visual Studio에서는 Chapter01 프로젝트를 시작 프로젝트로 선택하고 Ctrl+F5로 실행할 수 있습니다.

## 학습 목표

- 소스 파일, 프로젝트, 솔루션의 역할을 구분합니다.
- 문장 실행 순서와 콘솔 출력의 차이를 설명합니다.
- 콘솔 입력이 없을 가능성을 고려하여 안전하게 처리합니다.

## 실행 방법

```powershell
dotnet run --project chapters/01-ProgramBasics
dotnet run --project chapters/01-ProgramBasics -- --answers
```

첫 명령은 본문 예제를, 두 번째 명령은 연습문제 해설을 실행합니다.
기본 예제는 사용자 입력 없이 같은 결과를 재현하도록 구성했습니다.

## 1. C# 코드가 실행되기까지

우리가 쓰는 `Program.cs`는 사람이 읽는 소스 코드입니다.
컴파일러는 문법과 타입을 검사하고 실행에 필요한 결과물을 만듭니다.
.NET 런타임은 그 결과물을 실행하는 환경입니다.
따라서 C#이라는 **언어**, .NET이라는 **실행 환경과 라이브러리**, Visual Studio라는 **개발 도구**는 역할이 서로 다릅니다.

프로젝트 파일 `Chapter01.csproj`는 한 프로그램을 어떻게 빌드할지 설명합니다.
이 저장소의 공통 설정은 루트 `Directory.Build.props`에 있으므로 프로젝트 파일 자체는 짧습니다.
솔루션은 여러 프로젝트를 한곳에서 열어 관리하는 묶음입니다.
여기서는 단원마다 독립적인 실행 프로젝트가 있으므로 한 단원의 코드를 바꾸어도 다른 단원의 진입점과 충돌하지 않습니다.

빌드는 코드가 문법과 타입 규칙을 만족하는지 확인하는 단계입니다.
실행은 실제로 명령을 수행하는 단계입니다.
빌드에 성공해도 논리적인 계산이 틀리거나 실행 중 예외가 생길 수 있습니다.
그 때문에 결과를 예상하고 실제 출력과 비교하는 습관이 필요합니다.

## 2. 문장, 식, 블록을 읽는 법

`Console.WriteLine("안녕하세요");`는 콘솔에 한 줄을 출력하는 문장입니다.
문장 끝의 세미콜론 `;`은 명령 하나가 끝났다는 표시입니다.
`Console`은 콘솔 기능을 제공하는 타입이고, `WriteLine`은 그 타입의 메서드입니다.
괄호 안의 `"안녕하세요"`는 메서드에 전달하는 인수입니다.

`1 + 2`처럼 값을 만들어 내는 코드를 **식**이라고 합니다.
`int total = 1 + 2;`는 계산한 값을 변수에 넣는 문장입니다.
중괄호 `{ }`는 여러 문장을 하나의 블록으로 묶습니다.
들여쓰기는 실행 결과를 바꾸지는 않지만 블록 구조를 사람이 이해하는 데 필수적입니다.

`//` 뒤의 같은 줄은 한 줄 주석입니다.
`/* ... */`는 여러 줄 주석입니다.
주석에는 코드가 문자 그대로 하는 일을 반복하기보다 의도나 이유를 적으면 좋습니다.
C#은 대소문자를 구별하므로 `Console`과 `console`은 다른 이름입니다.

## 3. 최상위 문과 Main

이 프로젝트는 **최상위 문**으로 시작합니다.
C# 9부터 지원되는 이 형식에서는 메서드 바깥처럼 보이는 위치에 실행 코드를 쓸 수 있습니다.
실제로는 컴파일러가 프로그램 진입점에 해당하는 메서드를 생성합니다.

전통적인 형식은 다음과 같습니다.
아래 코드는 구조를 비교하기 위한 별도 예이며 현재 프로젝트에 그대로 덧붙이지 않습니다.

```csharp
class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("안녕하세요");
    }
}
```

최상위 문이 있는 파일은 한 프로젝트에 하나만 둘 수 있습니다.
`ExerciseSolutions.cs`는 타입과 메서드만 선언하므로 이 제한에 걸리지 않습니다.
공통 설정의 implicit usings 덕분에 `System`의 기본 타입을 쓰기 위한 `using System;`을 생략할 수 있습니다.
필요한 모든 네임스페이스가 자동 포함되는 것은 아니며, 다른 단원에서는 직접 `using`을 추가하기도 합니다.

## 4. 실습 1 — 출력 순서를 추적하기

[Program.cs](Program.cs)의 첫 번째 예제를 읽고 실행 전에 출력 줄 수를 예상하세요.

```csharp
Console.WriteLine("C# 문법 아틀라스");
Console.Write("학습 ");
Console.WriteLine("시작");
```

1. 첫 문장은 텍스트를 출력하고 다음 줄로 이동합니다.
2. 두 번째 문장은 텍스트를 출력하지만 줄을 바꾸지 않습니다.
3. 세 번째 문장이 같은 줄에 이어서 출력된 후 줄을 바꿉니다.

결과적으로 `학습 시작`은 하나의 줄입니다.
문장이 세 개라고 해서 출력 줄도 반드시 세 개인 것은 아닙니다.
화면에 보이는 공백 역시 문자열의 일부입니다.

## 5. 실습 2 — 값에 이름 붙이기

[Program.cs](Program.cs)의 `learner`와 `completed`를 찾아보세요.
문자열 `"민수"`와 정수 `1`을 각각 이름 있는 변수에 저장합니다.
그 다음 `$"학습자: {learner}"`처럼 문자열 보간으로 값을 끼워 넣습니다.

1. 변수 선언에서 이름과 값을 연결합니다.
2. 출력문이 실행될 때 현재 변수 값을 읽습니다.
3. 중괄호 안의 이름 대신 값이 표시됩니다.

지금은 `string`을 글자 데이터, `int`를 정수 데이터라고 이해하면 충분합니다.
자료형을 선택하는 기준은 02단원에서 더 자세히 다룹니다.
값 하나만 바꾼 후 다시 실행하여 출력에 반영되는지 확인하세요.

## 6. 실습 3 — 입력이 없을 수도 있다

기본 실행은 입력을 기다리지 않습니다.
직접 입력하는 실습은 아래 명령으로 선택합니다.

```powershell
dotnet run --project chapters/01-ProgramBasics -- --interactive
```

`--` 뒤의 값은 프로그램의 `args` 배열에 전달됩니다.
`args.Contains("--interactive")`가 참이면 입력 블록이 실행됩니다.
조건문과 배열은 뒤 단원에서 배우므로 지금은 실행 옵션을 구별하는 장치로 이해하세요.

```csharp
string? input = Console.ReadLine();
string name = string.IsNullOrWhiteSpace(input) ? "방문자" : input.Trim();
Console.WriteLine($"안녕하세요, {name}!");
```

`Console.ReadLine()`은 엔터까지의 문자열을 읽습니다.
입력 스트림이 끝나면 `null`을 반환할 수 있어서 타입을 `string?`로 표시합니다.
빈 문자열은 문자가 0개인 문자열이고, `null`은 문자열 자체가 없음을 나타냅니다.
`IsNullOrWhiteSpace`로 null, 빈 문자열, 공백만 있는 입력을 함께 검사합니다.
그 경우 방문자를 사용하고, 실제 이름이 있으면 `Trim()`으로 양끝 공백을 제거합니다.

## 7. 자주 하는 실수와 원인

- `Console.Writeline`: 이름의 대소문자가 달라 메서드를 찾지 못합니다. `WriteLine`을 사용하세요.
- 문자열을 작은따옴표로 묶기: 작은따옴표는 한 `char`에 사용합니다. 여러 글자는 큰따옴표를 사용합니다.
- 세미콜론 누락: 오류가 다음 줄에서 표시될 수도 있으므로 직전 줄까지 확인하세요.
- 문장 밖에 닫는 중괄호 추가: 들여쓰기와 짝이 맞는 중괄호를 함께 확인하세요.
- `ReadLine()!.Trim()` 사용: `!`는 null을 없애지 않습니다. 실제 null이면 실행 중 예외가 생깁니다.

오류를 볼 때는 맨 앞 오류부터 고치는 편이 좋습니다.
하나의 괄호 누락이 뒤쪽의 여러 오류를 연쇄적으로 만들 수 있기 때문입니다.
Visual Studio의 오류 목록에서 오류를 더블클릭한 뒤, 해당 줄과 앞뒤 문맥을 확인하세요.

## 복습 질문

### 1. 빌드 성공은 프로그램이 의도대로 동작한다는 뜻인가요?

<details>
<summary>정답</summary>

아닙니다. 문법·타입 검사와 논리적 정확성은 별개이므로 실행 결과도 확인해야 합니다.

</details>

### 2. Write와 WriteLine의 차이는 무엇인가요?

<details>
<summary>정답</summary>

WriteLine은 출력 뒤 줄을 바꾸고 Write는 현재 줄에 계속 출력합니다.

</details>

### 3. string?의 물음표는 어떤 의도인가요?

<details>
<summary>정답</summary>

문자열이 null일 수도 있음을 타입 분석에 알리며, 사용 전에 그 경우를 처리하도록 돕습니다.

</details>
