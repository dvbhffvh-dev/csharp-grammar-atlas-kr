## 1. 변수는 값에 붙이는 이름입니다

변수를 선언한다는 것은 이름과 타입을 도입하는 일입니다.
초기화는 처음 값을 넣는 일이며, 대입은 이후에도 값을 바꾸는 연산입니다.
한 문장에서 선언과 초기화를 함께 할 수 있습니다.

```csharp
int quantity = 3;
quantity = 5;
```

`int`는 타입, `quantity`는 이름, `3`은 초기값입니다.
두 번째 문장의 `=`는 두 값이 같다는 수학 기호가 아니라 오른쪽 결과를 왼쪽에 저장하는 연산자입니다.
따라서 `quantity = quantity + 1;`도 올바릅니다.
기존 값을 읽고 1을 더한 결과를 다시 저장하는 순서로 실행됩니다.

좋은 이름은 값이 무엇인지 알려줍니다.
`x`보다 `quantity`, `v`보다 `unitPrice`가 상품 계산을 설명하기 쉽습니다.
지역 변수는 보통 `camelCase`를 사용하지만 이름 규칙은 문법 자체와 구별해야 합니다.

## 2. 어떤 타입을 골라야 할까요?

| 타입 | 주로 담는 값 | 예 |
| --- | --- | --- |
| `int` | 보통 크기의 정수 | 수량, 나이 |
| `long` | 더 넓은 범위의 정수 | 큰 누적 횟수 |
| `double` | 근삿값을 허용하는 실수 | 센서 측정값 |
| `decimal` | 십진수 계산이 중요한 값 | 금액 |
| `bool` | 참 또는 거짓 | 판매 가능 여부 |
| `char` | UTF-16 코드 단위 하나 | `'A'` |
| `string` | 텍스트 | `"노트"` |

`int`의 범위는 -2,147,483,648부터 2,147,483,647까지입니다.
범위를 넘을 수 있는 값을 억지로 int에 넣지 말고 데이터 요구사항에 맞게 타입을 선택하세요.
`long` 리터럴에는 `L`을 붙이면 타입 의도가 명확합니다.
숫자 안의 밑줄은 읽기 편하도록 넣는 구분자이며 실제 값에는 영향을 주지 않습니다.

`double`은 이진 부동소수점이어서 0.1 같은 일부 십진 소수를 정확히 저장하지 못합니다.
`decimal`은 십진 기반 계산에 적합하지만 모든 분수나 무한히 큰 값을 정확하게 표현하는 만능 타입은 아닙니다.
금액에도 소수 자리 반올림 정책은 별도로 필요합니다.
`12.50m`의 `m`은 decimal 리터럴이며, suffix 없는 `12.50`은 double입니다.

`char`는 화면에 보이는 글자 하나와 항상 일치하지 않습니다.
예를 들어 일부 이모지는 여러 UTF-16 코드 단위로 표현됩니다.
텍스트 길이와 사용자에게 보이는 글자 수의 차이는 04단원에서 확인합니다.

## 3. var는 타입을 없애지 않습니다

```csharp
var quantity = 3;       // 컴파일러가 int로 결정합니다.
var product = "노트";   // 컴파일러가 string으로 결정합니다.
```

컴파일러는 오른쪽 초기화 식으로 변수의 타입을 결정합니다.
그 이후 `quantity = "세 개";`처럼 다른 타입 값을 대입할 수 없습니다.
따라서 var는 동적으로 타입이 바뀌는 기능이 아닙니다.
`var value;`처럼 초기값 없이 선언할 수도 없습니다.

값의 의미가 바로 드러날 때 var는 중복을 줄여 줍니다.
학습 초기에는 `int quantity`처럼 타입을 직접 써서 값의 성격을 익혀도 좋습니다.
중요한 것은 두 방식 모두 컴파일 시 타입 검사를 받는다는 점입니다.

## 5. 실습 2 — 금액 계산과 const

```csharp
decimal price = 12.50m;
var quantity = 3;
const decimal TaxRate = 0.10m;
decimal total = price * quantity;
```

1. 단가와 수량으로 총액 37.50을 계산합니다.
2. 컴파일 시 확정되는 세율을 `const`로 선언합니다.
3. 총액에 세율을 곱하여 세금 3.75를 계산합니다.
4. `F2` 서식으로 소수점 이하 두 자리를 표시합니다.

`const`는 선언할 때 컴파일 시 상수로 초기화해야 하며 나중에 다시 대입할 수 없습니다.
현재 시각이나 파일에서 읽은 값처럼 실행 중에 알아내는 값은 const로 만들 수 없습니다.
`readonly` 필드는 선언 또는 해당 타입의 생성자에서 초기화할 수 있어 실행 중 결정되는 값을 담을 수 있습니다.
readonly는 일반 지역 변수에 const 대신 붙이는 키워드가 아닙니다.

클래스의 필드와 생성자는 뒤 단원에서 다루므로 여기서는 차이만 기억하세요.
readonly 참조 필드가 있다고 해서 그 필드가 가리키는 객체 내부까지 모두 변경 불가능해지는 것은 아닙니다.
값 변경을 막는 범위가 어디인지 확인해야 합니다.

이 프로젝트는 출력 비교를 위해 `CultureInfo.InvariantCulture`를 사용합니다.
실제 사용자용 앱에서는 사용자의 지역별 숫자 표시 방식이 필요할 수 있습니다.
숫자 값과 숫자를 화면에 쓰는 형식은 별개의 문제입니다.

## 6. 실습 3 — 미입력과 0점 구별하기

[Program.cs](Program.cs)의 `optionalScore`는 `int?` 타입입니다.
`int`는 정수 값만 표현하지만 `int?`는 null도 표현할 수 있습니다.
점수를 아직 입력하지 않은 상태와 실제로 0점을 받은 상태를 구별할 수 있습니다.

```csharp
int? optionalScore = null;
Console.WriteLine(optionalScore ?? -1);
optionalScore = 90;
Console.WriteLine(optionalScore.Value);
```

`??`는 왼쪽이 null일 때만 오른쪽 기본값을 선택합니다.
여기서 -1은 화면에서 미입력을 보여주기 위한 임시 표시이며 모든 시스템에서 통용되는 규칙은 아닙니다.
`Value`는 값이 있을 때만 읽어야 합니다.
예제에서는 바로 앞에서 90을 넣었지만 일반 코드에서는 `HasValue` 또는 패턴 검사를 먼저 합니다.

nullable 참조 타입 `string?`와 nullable 값 타입 `int?`는 목적이 비슷해 보여도 구현 방식은 다릅니다.
이 차이와 값·참조의 동작은 09단원에서 이어집니다.

## 7. 실습 4 — 초기화와 재대입

지역 변수 `count`는 선언만 하고 바로 읽을 수 없습니다.
컴파일러는 모든 실행 경로에서 값이 확정적으로 대입되었는지 검사합니다.
반면 배열의 새 요소 등에는 타입의 기본값이 적용되며, 모든 저장 위치가 동일한 규칙인 것은 아닙니다.

예제에서 5를 넣고 2를 더하므로 마지막 값은 7입니다.
`count = count + 2`는 `count += 2`로 줄여 쓸 수 있습니다.
연산자 동작은 다음 단원에서 더 자세히 살펴봅니다.

## 8. 자주 하는 실수와 원인

- `decimal price = 1.5;`: 오른쪽은 double입니다. `1.5m`을 사용하세요.
- `bool flag = 1;`: C#에서는 정수가 자동으로 bool이 되지 않습니다.
- 초기화하지 않은 지역 변수 읽기: 모든 경로에서 먼저 값을 대입해야 합니다.
- null 점수의 `Value` 접근: 값이 없으므로 예외가 발생합니다.
- var를 dynamic과 혼동하기: var의 타입은 컴파일 시 고정됩니다.
