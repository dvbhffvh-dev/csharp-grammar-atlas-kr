## 1. 텍스트와 문자열 리터럴

string은 System.String을 가리키는 C# 키워드입니다.
큰따옴표로 감싼 `"C# 학습"`은 문자열 리터럴입니다.
작은따옴표 `'C'`는 char 리터럴이며 두 타입은 다릅니다.
빈 문자열 `""`도 유효한 문자열이고 Length는 0입니다.

문자열의 Length는 UTF-16 코드 단위 수입니다.
일상적으로 말하는 글자 수와 항상 같지는 않습니다.
일부 이모지는 여러 코드 단위로 표현되므로 한 이모지의 Length가 2일 수 있습니다.
사용자가 보는 글자 단위로 편집하려면 단순한 인덱스 이동 이상의 처리가 필요할 수 있습니다.

## 2. 실습 1 — 이스케이프와 축자 문자열

큰따옴표와 역슬래시는 문자열 문법에도 쓰입니다.
일반 문자열에 그대로 넣으려면 이스케이프를 사용합니다.

| 표기 | 실제 의미 |
| --- | --- |
| `\"` | 큰따옴표 |
| `\\` | 역슬래시 하나 |
| `\n` | 줄바꿈 문자 |
| `\t` | 탭 문자 |

[Program.cs](Program.cs)의 두 경로 문자열을 비교하세요.

```csharp
string escaped = "C:\\Study\\CSharp";
string verbatim = @"C:\Study\CSharp";
```

1. 일반 문자열은 역슬래시를 두 번 적어 실제 한 개를 나타냅니다.
2. @가 붙은 축자 문자열에서는 역슬래시를 그대로 적습니다.
3. 표기법은 달라도 값이 같아서 비교 결과는 True입니다.

이 경로는 문자열 표기 예시이며 폴더나 파일을 만들지 않습니다.
축자 문자열에 큰따옴표를 넣을 때는 큰따옴표를 두 번 씁니다.
`@"그가 ""안녕""이라고 말했다"`는 큰따옴표를 포함한 문장을 만듭니다.
@는 모든 문법을 무시한다는 뜻이 아니라 이스케이프 해석 방식을 바꾸는 표기입니다.

## 3. 실습 2 — 보간과 숫자 서식

$를 붙이면 중괄호 안의 식을 평가하여 문자열 안에 넣습니다.

```csharp
string learner = "지우";
decimal price = 1234.5m;
Console.WriteLine($"{learner}의 가격: {price:F2}");
```

1. learner의 현재 값이 첫 중괄호 위치에 들어갑니다.
2. price를 읽은 뒤 F2 서식을 적용합니다.
3. 최종 문자열을 WriteLine에 전달합니다.

F2는 고정 소수점 형식에서 소수점 이하 두 자리를 표시합니다.
표시 방법이 달라질 뿐 price 변수에 저장된 숫자 자체는 바뀌지 않습니다.
원래 숫자는 계속 계산에 사용할 수 있습니다.

문화권에 따라 소수 구분자와 날짜 형식이 달라질 수 있습니다.
예제는 예상 출력 비교를 위해 InvariantCulture를 사용합니다.
사용자용 앱에서는 문화권 선택을 요구사항에 맞추세요.

일반 보간 문자열에 중괄호 자체를 넣으려면 {{와 }}를 씁니다.
복잡한 식을 전부 보간 안에 넣기보다 먼저 변수로 계산하면 읽기 쉽습니다.

## 4. 실습 3 — raw 문자열 리터럴

raw 문자열 리터럴은 C# 11부터 지원됩니다.
최소 큰따옴표 세 개로 시작하고 같은 개수의 큰따옴표로 끝납니다.
JSON이나 여러 줄 문장을 소스에 넣을 때 이스케이프를 줄일 수 있습니다.

```csharp
string json = """{"name":"지우","level":1}""";
```

[Program.cs](Program.cs)는 JSON 텍스트를 출력하며 실제 JSON 파싱은 수행하지 않습니다.
내용 속 큰따옴표 앞에 역슬래시를 붙이지 않아도 되는 점을 확인하세요.
큰따옴표 세 개가 연속된 내용이 필요하면 바깥 구분자를 더 길게 잡을 수 있습니다.

여러 줄 raw 문자열은 시작 구분자 다음 줄에서 내용을 시작합니다.
닫는 구분자의 들여쓰기가 제거할 공통 들여쓰기의 기준이 됩니다.

```csharp
string message = """
    첫 번째 줄
    두 번째 줄
    """;
```

위 값에는 두 문장 사이의 줄바꿈이 들어갑니다.
시작과 종료를 표시하기 위한 구조용 줄바꿈은 실제 내용과 구별됩니다.
닫는 구분자와 본문의 들여쓰기 규칙이 맞지 않으면 컴파일 오류가 날 수 있습니다.
raw는 소스에서 문자열을 적는 방식이며 별도의 데이터 타입은 아닙니다.

## 5. 실습 4 — 가공 결과를 받아야 하는 이유

문자열은 불변입니다.
Trim이나 Replace를 호출해도 기존 문자열의 글자가 제자리에서 바뀌지 않습니다.
가공된 문자열을 반환하므로 결과를 받아 사용해야 합니다.

```csharp
string original = "  csharp  ";
string normalized = original.Trim().ToUpperInvariant();
```

1. original은 양끝 공백을 포함한 원본을 계속 유지합니다.
2. Trim은 양끝 공백을 제거한 값을 반환합니다.
3. 그 결과에 ToUpperInvariant를 호출합니다.
4. 최종 값을 normalized에 저장합니다.

원본 길이는 여전히 10이고 새 값은 CSHARP입니다.
`original.Trim();`만 호출하고 결과를 버리면 원본은 달라지지 않습니다.

Split은 구분자를 기준으로 문자열 배열을 만듭니다.
Join은 요소 사이에 구분자를 넣어 하나의 문자열로 합칩니다.
예제에서는 쉼표로 나눈 단어를 슬래시 구분자로 다시 합칩니다.
배열의 자세한 구조는 07단원에서 배웁니다.

## 6. 비교 기준을 명시하기

사람의 언어를 정렬하는 기준과 내부 식별자를 비교하는 기준은 다를 수 있습니다.
명령어, 키, 프로토콜 값처럼 문화권과 무관한 식별자는 Ordinal 계열 비교를 고려하세요.
예제는 StartsWith에 StringComparison.Ordinal을 명시합니다.

```csharp
bool same = string.Equals(
    "save", "SAVE", StringComparison.OrdinalIgnoreCase);
```

대소문자를 무시할 목적이라면 비교 옵션으로 직접 드러낼 수 있습니다.
무조건 양쪽을 소문자로 바꾼 뒤 비교하는 방법보다 의도를 읽기 쉽습니다.
사용자 언어에 맞는 정렬과 검색에는 다른 비교 기준이 필요할 수 있습니다.

## 7. StringBuilder의 역할

반복해서 많은 조각을 더하면 중간 문자열을 많이 만들 수 있습니다.
StringBuilder는 내부 버퍼로 텍스트를 조립하고 ToString으로 결과를 제공합니다.
예제는 Append를 세 번 호출해 C# 학습이라는 텍스트를 만듭니다.

짧은 문자열 몇 개에는 보간이나 Join이 더 간단할 수 있습니다.
StringBuilder가 항상 더 빠르다고 단정하지 말고 작업 형태와 측정 결과를 기준으로 선택하세요.
using System.Text는 StringBuilder를 짧은 이름으로 사용하기 위한 선언입니다.

## 8. 자주 하는 실수

- `"C:\new"`를 경로로 쓰기: \n이 줄바꿈으로 해석됩니다. 축자 문자열이나 이중 역슬래시를 쓰세요.
- Trim 반환값 버리기: 문자열은 불변이라 결과를 받아야 합니다.
- Length를 눈에 보이는 글자 수로 간주: 이모지나 결합 문자에서 틀릴 수 있습니다.
- null에 메서드 호출: 먼저 null을 처리하거나 기본값 정책을 정하세요.
- raw 문자열을 구형 프로젝트에 복사: C# 11 이상 설정인지 확인하세요.
