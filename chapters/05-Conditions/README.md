## 1. 조건문은 실행할 문장을 선택합니다

지금까지 문장은 대체로 위에서 아래로 모두 실행되었습니다.
조건문은 판단 결과에 따라 일부 문장만 실행하도록 만듭니다.
C#의 if 괄호 안에는 bool 식이 와야 합니다.
정수 1이나 빈 문자열을 자동으로 참·거짓으로 해석하지 않습니다.

```csharp
int stock = 3;
if (stock > 0)
{
    Console.WriteLine("주문 가능합니다.");
}
else
{
    Console.WriteLine("품절입니다.");
}
```

stock > 0을 한 번 평가하고 true이면 첫 블록, false이면 else 블록을 실행합니다.
둘 중 하나만 선택하며 양쪽을 모두 실행하지 않습니다.
else가 없는 if는 조건이 false이면 해당 블록을 건너뜁니다.

한 문장이라 중괄호를 생략할 수 있어도 학습 코드에서는 항상 쓰는 편이 안전합니다.
나중에 줄을 추가하면서 그 줄도 조건 안에 있다고 착각하는 오류를 줄여 줍니다.
들여쓰기는 실행 범위를 정하지 않고 중괄호가 실제 범위를 정합니다.

## 2. 실습 1 — 점수에서 등급 계산하기

[Program.cs](Program.cs)는 점수 87을 등급 B로 바꿉니다.
if, else if, else는 위에서부터 검사하고 처음 참인 분기 하나만 실행합니다.

```csharp
if (score >= 90)
{
    grade = "A";
}
else if (score >= 80)
{
    grade = "B";
}
else
{
    grade = "재도전";
}
```

1. 87 >= 90은 false여서 첫 블록을 건너뜁니다.
2. 87 >= 80은 true여서 grade에 B를 대입합니다.
3. 뒤쪽 분기는 더 검사하지 않습니다.
4. 블록을 나온 뒤 확정된 grade를 출력합니다.

실제 프로그램에는 70점 이상인 C 분기도 있습니다.
각 분기의 범위를 종이에 적어 서로 겹치는 조건의 순서를 확인하세요.
높은 점수부터 검사하면 80~89라는 조건을 매번 길게 쓰지 않아도 됩니다.

`score >= 70`을 맨 앞에 두면 95점도 그 분기에 걸립니다.
조건의 순서는 단순한 보기 문제가 아니라 동작을 결정합니다.
else가 있어 모든 경로에서 grade가 대입되므로 이후 안전하게 읽을 수 있습니다.

## 3. 독립 if와 else if는 다릅니다

다음 두 조건은 각각 독립적으로 실행됩니다.

```csharp
if (score >= 80)
{
    Console.WriteLine("우수 점수");
}
if (score >= 90)
{
    Console.WriteLine("장학 후보");
}
```

95점이면 두 문장이 모두 출력됩니다.
하나의 등급만 정하려면 else if 연결이 적합하고,
동시에 여러 특성을 알리려면 독립 if가 적합할 수 있습니다.
문제를 먼저 말로 설명한 뒤 한 경로만 필요한지 여러 조건이 각각 필요한지 판단하세요.

## 4. 실습 2 — 복합 조건에 이름 붙이기

[Program.cs](Program.cs)는 나이와 입장권을 함께 검사합니다.

```csharp
bool canEnter = age >= 18 && hasTicket;
Console.WriteLine(canEnter ? "입장 가능" : "입장 불가");
```

1. age >= 18로 나이 조건을 판단합니다.
2. &&를 통해 입장권 조건도 충족해야 하는지 결합합니다.
3. canEnter라는 이름으로 판단의 의미를 표현합니다.
4. 그 결과에 맞는 메시지를 선택합니다.

조건이 길어질수록 의미 있는 bool 변수가 도움이 됩니다.
`!isBlocked`와 `hasPermission`처럼 조건의 긍정·부정 관계도 읽기 쉽게 유지하세요.
AND와 OR가 섞이면 괄호로 의도한 묶음을 드러내는 것이 좋습니다.

조건을 작성할 때는 참이 되는 예만 보지 말고 거짓이 되는 예도 넣으세요.
나이 17/18, 입장권 있음/없음처럼 경계 양쪽의 사례를 손으로 추적할 수 있습니다.

## 5. 실습 3 — switch 문으로 명령 분류하기

switch는 하나의 값과 여러 case를 비교해 실행할 구역을 선택합니다.
예제의 command는 save이므로 저장 명령이 출력됩니다.

```csharp
switch (command)
{
    case "save":
        Console.WriteLine("저장 명령");
        break;
    case "quit":
    case "exit":
        Console.WriteLine("종료 명령");
        break;
    default:
        Console.WriteLine("알 수 없는 명령");
        break;
}
```

1. command 값을 확인합니다.
2. 일치하는 case의 문장들을 실행합니다.
3. break로 switch 문을 빠져나옵니다.
4. 어느 case도 맞지 않으면 default를 실행합니다.

quit와 exit는 문장 없는 case 레이블을 이어서 같은 동작을 공유합니다.
실행문이 있는 case에서 다음 case로 자동으로 흘러가는 코드는 허용되지 않습니다.
분기 끝에는 break, return, throw 등 제어 흐름을 끝내거나 이동시키는 문장이 필요합니다.

문자열 case 비교는 이 예제에서 대소문자를 구별합니다.
SAVE도 받아야 한다면 입력 정규화 등 정책을 정한 다음 비교하세요.
switch 식과 패턴 매칭은 뒤 단원에서 확장해서 배웁니다.

## 6. 실습 4 — 조건 연산자는 값을 만듭니다

if가 문장을 선택한다면 조건 연산자 `?:`는 두 식 중 하나의 값을 선택합니다.

```csharp
int shipping = quantity >= 3 ? 0 : 3000;
```

조건이 참이면 0, 거짓이면 3000을 선택해 shipping에 저장합니다.
선택되지 않은 쪽의 식은 실행하지 않습니다.
값 하나를 고르는 간단한 조건에 적합합니다.

여러 일을 하거나 조건을 깊게 중첩해야 한다면 if 문이 더 읽기 쉬울 수 있습니다.
짧은 줄 수보다 의도와 실행 흐름이 명확한지가 중요합니다.
중첩된 ?:를 연속으로 붙이기 전에 변수나 메서드로 의미를 나눌 수 있는지 보세요.

## 7. 정상 범위와 잘못된 입력을 구분하기

실제 점수는 0~100이어야 한다고 가정합니다.
먼저 `score < 0 || score > 100`을 검사하면 잘못된 범위를 잡을 수 있습니다.
두 조건 중 하나만 맞아도 범위를 벗어나므로 OR를 사용합니다.
AND로 연결하면 한 숫자가 동시에 0 미만이면서 100 초과일 수 없어 검사가 무효가 됩니다.

프로그램 마지막의 invalidScore = -1은 이 경로를 의도적으로 보여줍니다.
형식 검증, 값 범위 검증, 등급 계산을 구별하면 오류 원인을 설명하기 쉬워집니다.
03단원의 TryParse와 함께 사용하면 텍스트 입력부터 안전하게 처리할 수 있습니다.

## 8. 자주 하는 실수

- `if (condition);`: 세미콜론이 빈 문장이 되어 뒤 블록이 조건과 무관하게 실행될 수 있습니다.
- 조건 순서를 낮은 점수부터 작성: 넓은 조건이 구체적인 조건을 먼저 가로챕니다.
- else가 어느 if에 붙는지 착각: 중괄호로 블록을 명확히 하세요.
- `0 <= score <= 100`: C#에서는 이렇게 연쇄 비교할 수 없습니다. 두 비교를 &&로 연결하세요.
- 정상 값만 검사: 경계 바로 아래·위와 잘못된 값도 확인하세요.
