## 1. 메서드는 이름 있는 작업 단위입니다

같은 계산을 여러 곳에 복사하면 규칙을 바꿀 때 모든 복사본을 수정해야 합니다.
메서드는 작업을 한곳에 정의하고 이름으로 호출할 수 있게 합니다.
하지만 코드가 두 번 나온다는 이유만으로 무조건 묶기보다는, 하나의 의미 있는 책임을 맡기는 것이 좋습니다.
예를 들어 Add는 두 값을 더하고 Greet는 인사말을 만듭니다.

```csharp
public static int Add(int left, int right)
{
    return left + right;
}
```

public은 다른 코드에서 접근할 수 있음을 나타냅니다.
static은 객체를 생성하지 않고 타입 이름을 통해 호출할 수 있는 메서드임을 나타냅니다.
int는 반환 타입이며 Add는 메서드 이름입니다.
괄호 안의 left와 right는 입력을 받는 매개변수입니다.

`Add(2, 3)`에서 2와 3은 호출자가 전달한 인수입니다.
매개변수는 정의에 있는 이름이고 인수는 실제 호출 시 전달하는 값이라는 차이를 구별하세요.
호출 시 인수가 매개변수에 전달되고 본문이 실행됩니다.
return이 실행되면 계산 결과를 호출한 위치로 돌려주며 해당 메서드를 끝냅니다.

반환할 값이 없다면 반환 타입에 void를 사용합니다.
void 메서드도 `return;`으로 실행을 일찍 끝낼 수 있습니다.
값을 반환하는 메서드는 정상적으로 끝나는 모든 경로에서 해당 타입의 값을 반환해야 합니다.

```csharp
public static int Add(int left, int right) => left + right;
```

위 코드는 단일 식으로 결과를 계산하는 식 본문 메서드입니다.
짧은 계산을 간결하게 쓰는 문법이지 실행 방식이 완전히 다른 함수는 아닙니다.
판단과 작업이 여러 단계이면 중괄호 본문이 더 읽기 쉬울 수 있습니다.

## 2. 실습 1 — 기본값과 이름 있는 인수

[Program.cs](Program.cs)의 Greet는 이름과 호칭을 받아 문자열을 반환합니다.

```csharp
public static string Greet(string name, string suffix = "씨")
{
    return $"안녕하세요, {name}{suffix}!";
}
```

1. `Greet("지우")`는 필수 인수 name만 전달합니다.
2. 생략한 suffix에는 기본값 씨가 사용됩니다.
3. 반환된 문자열을 Console.WriteLine이 출력합니다.
4. `Greet(suffix: "님", name: "민수")`는 매개변수 이름을 적어 값을 전달합니다.

기본값이 있는 매개변수는 호출 시 생략할 수 있습니다.
보통 필수 매개변수 뒤에 선택적 매개변수를 배치합니다.
일반적인 선택적 매개변수의 기본값에는 상수처럼 언어가 허용하는 기본값 표현식을 사용해야 합니다.
`DateTime.Now`처럼 호출할 때마다 달라지는 임의의 식을 그대로 기본값으로 쓸 수는 없습니다.

이름 있는 인수는 bool 여러 개나 단위가 비슷한 숫자를 전달할 때 특히 읽기 쉽습니다.
전부 이름을 붙이면 예제처럼 선언 순서와 다르게 적어도 대상 매개변수가 명확합니다.
인수 이름은 메서드의 실제 매개변수 이름과 같아야 합니다.
위치 인수와 이름 있는 인수를 복잡하게 섞기보다 일관된 호출 형식을 사용하세요.

Greet는 직접 화면에 출력하지 않고 문자열을 반환합니다.
따라서 호출자가 화면 출력, 파일 저장, 문자열 비교 등 사용 방법을 선택할 수 있습니다.
계산과 출력 책임을 분리하면 메서드를 다른 곳에서 재사용하기도 쉬워집니다.

## 3. 같은 이름을 가진 메서드 — 오버로드

예제에는 int를 받는 Add와 double을 받는 Add가 있습니다.

```csharp
public static int Add(int left, int right) => left + right;
public static double Add(double left, double right) => left + right;
```

`Add(2, 3)`은 int 인수에 맞는 오버로드를 호출합니다.
`Add(2.5, 3.5)`는 double 인수에 맞는 오버로드를 호출합니다.
컴파일러는 인수 타입과 허용된 변환 등을 고려하여 적용 가능한 메서드를 선택합니다.
호출이 모호하면 컴파일 오류가 나므로 타입이나 메서드 이름을 더 명확히 해야 합니다.

반환 타입만 다르게 바꾸어 오버로드할 수는 없습니다.
매개변수 이름만 다르거나 기본값만 다른 선언도 별도 오버로드를 만들지 못합니다.
ref와 out만 바꿔 같은 형태의 오버로드를 만드는 것도 허용되지 않습니다.
처음에는 매개변수의 개수나 타입이 분명하게 다른 오버로드부터 사용하세요.

## 4. 실습 2 — 일반 전달과 ref

기본적으로 인수는 값으로 전달됩니다.
int 인수에서는 정수 값의 복사본이 매개변수에 들어갑니다.

```csharp
int value = 10;
MathExamples.IncreaseCopy(value);
Console.WriteLine(value);
```

IncreaseCopy의 value++는 메서드가 받은 복사본을 바꿉니다.
호출자의 value는 여전히 10이므로 출력은 10입니다.
이름이 같다고 두 지역 변수가 같은 저장 위치를 사용하는 것은 아닙니다.

ref를 사용하면 호출자의 변수를 참조하여 읽고 바꿀 수 있습니다.

```csharp
public static void Increase(ref int value)
{
    value++;
}

MathExamples.Increase(ref value);
```

정의와 호출 양쪽에 ref를 적습니다.
호출 전에 변수에 값을 대입해 두어야 합니다.
예제에서 호출자의 value가 10에서 11로 바뀝니다.
반환값 없이도 외부 상태가 달라지므로 호출부에서 그 가능성을 알아볼 수 있어야 합니다.

참조 타입을 보통 방식으로 전달하는 것과 ref 전달은 다릅니다.
참조 타입을 값으로 전달하면 객체를 가리키는 참조의 복사본을 받습니다.
그 복사본으로 같은 객체의 내부를 바꿀 수 있지만, 매개변수에 새 객체를 대입한다고 호출자의 변수까지 바뀌지는 않습니다.
이 차이는 다음 단원에서 직접 실행하며 확인합니다.

## 5. 실습 3 — out, in과 params

TryDivide는 성공 여부를 bool로 반환하고 몫과 나머지를 out으로 돌려줍니다.

```csharp
bool success = MathExamples.TryDivide(
    17, 5, out int quotient, out int remainder);
```

1. 호출할 때 out 변수에 미리 값을 넣을 필요는 없습니다.
2. 메서드는 정상적으로 반환하는 모든 경로에서 out 매개변수에 값을 대입해야 합니다.
3. 예제는 먼저 몫과 나머지를 0으로 초기화합니다.
4. 나눌 수 있으면 실제 결과를 넣고 true를 반환합니다.

17을 5로 나누면 몫은 3, 나머지는 2입니다.
0으로 나누는 경우와 int.MinValue를 -1로 나누어 int 범위를 넘는 경우에는 false를 반환합니다.
실패 시의 0은 정상 계산 결과가 아니므로 먼저 success를 확인해야 합니다.
03단원의 TryParse와 같은 성공 여부 + 추가 결과 패턴입니다.

in은 읽기 전용 참조 전달을 표현합니다.

```csharp
public static int Square(in int value) => checked(value * value);
```

메서드 안에서 in 매개변수 자체에 새 값을 대입할 수 없습니다.
예제는 4를 받아 제곱 16을 반환합니다.
작은 int를 in으로 전달하면 항상 더 빠르다는 뜻은 아니며 여기서는 문법을 관찰하는 용도입니다.
큰 구조체의 복사 비용을 고려할 때도 실제 성능은 측정해야 합니다.

참조 타입에 in을 붙여도 객체 내부까지 불변으로 만드는 것은 아닙니다.
읽기 전용인 대상은 전달받은 참조 변수이지 객체 전체의 모든 상태가 아닙니다.
호출부에서 in을 명시할 수 있으며 이 예제는 의미를 보이기 위해 명시합니다.

| 방식 | 호출 전 초기화 | 메서드의 매개변수 대입 | 핵심 의도 |
| --- | --- | --- | --- |
| 일반 | 필요 | 복사본 변경 가능 | 값을 입력으로 전달 |
| ref | 필요 | 호출자 변수 변경 가능 | 기존 값을 읽고 수정 |
| out | 불필요 | 정상 반환 전 대입 필수 | 추가 결과 제공 |
| in | 읽을 값 필요 | 매개변수 자체 변경 불가 | 읽기 전용 참조 전달 |

params는 같은 타입의 인수를 여러 개 전달하는 호출을 지원합니다.
예제의 `Sum(params int[] numbers)`는 배열 기반 params 형식입니다.
`Sum(1, 2, 3, 4)`처럼 호출하거나 int 배열 하나를 전달할 수 있습니다.
`Sum()`처럼 인수를 생략하면 빈 배열을 처리하여 이 구현에서는 0을 반환합니다.
params 매개변수는 매개변수 목록의 마지막에 하나만 둘 수 있습니다.

Sum은 각 숫자를 checked로 더합니다.
결과가 int 범위를 넘으면 조용히 잘못된 합을 반환하는 대신 예외로 알립니다.
입력을 어떤 범위까지 지원할지는 메서드의 계약에 포함되어야 합니다.

## 6. 지역 변수와 범위

메서드의 매개변수와 지역 변수는 그 메서드 호출에 속합니다.
다른 메서드의 지역 변수를 이름만으로 직접 읽을 수 없습니다.
필요한 정보는 인수로 전달하거나 반환값으로 돌려주는 방식으로 연결하세요.

if나 반복문의 중괄호 안에 선언한 지역 변수는 그 블록 밖에서 사용할 수 없습니다.
같은 이름을 중첩된 범위에 다시 선언하는 것도 제한될 수 있습니다.
범위 규칙은 이름 충돌과 잘못된 상태 접근을 줄여 줍니다.

Program.cs는 최상위 실행문 뒤에 MathExamples 타입을 선언합니다.
타입 선언 자체가 그 위치에서 모든 메서드를 실행한다는 뜻은 아닙니다.
메서드는 호출된 순간에만 본문을 실행합니다.
ExerciseSolutions.Run 역시 --answers 조건을 만족할 때만 호출됩니다.

## 7. 실습 4 — 안전한 범위의 재귀

재귀는 메서드가 자기 자신을 호출하는 방식입니다.
팩토리얼은 n! = n × (n - 1)!이라는 규칙을 코드로 표현하기 좋습니다.
하지만 반드시 더 작은 문제로 진행해야 하고 멈추는 조건이 있어야 합니다.

```csharp
if (number <= 1)
{
    return 1;
}
return checked(number * Factorial(number - 1));
```

1. Factorial(5)는 5 × Factorial(4)를 계산합니다.
2. 입력을 하나씩 줄이며 Factorial(1)까지 내려갑니다.
3. Factorial(1)은 1을 반환하여 추가 호출을 멈춥니다.
4. 돌아오며 2, 6, 24, 120을 계산합니다.

0!도 정의상 1이므로 number <= 1 조건에 포함됩니다.
예제는 음수와 20보다 큰 입력을 먼저 거부합니다.
20!은 long 범위에 들어가지만 21!은 들어가지 않기 때문입니다.
입력 상한은 호출 깊이까지 작게 제한하여 이 예제를 안전하게 실행하게 합니다.

일반적인 재귀에는 호출마다 스택 사용 비용이 생길 수 있습니다.
종료 조건만 있다고 매우 깊은 호출까지 안전한 것은 아닙니다.
C#에서 모든 재귀가 자동으로 반복문처럼 최적화된다고 가정하지 마세요.
작업에 따라 반복문이 더 단순하고 적합할 수 있습니다.

## 8. 자주 하는 실수

- 메서드를 선언만 하고 실행을 기대: 메서드 호출이 있어야 본문이 실행됩니다.
- 반환값을 버리고 출력되기를 기대: return과 Console.WriteLine의 책임을 구별하세요.
- 매개변수 이름과 호출자 이름이 같으면 같은 변수라고 생각: 일반 전달은 복사입니다.
- out 결과만 사용하고 성공 여부 무시: 실패의 기본값을 정상 결과로 오인할 수 있습니다.
- 반환 타입만 바꾸어 오버로드: 호출 구분 기준으로 충분하지 않아 컴파일 오류가 납니다.
- 재귀에서 입력이 줄지 않거나 종료 조건 누락: 호출이 끝나지 않을 수 있습니다.

<details>
<summary>해설과 실행 가능한 정답</summary>

Max는 비교 결과에 따라 한 값을 반환합니다.
Swap은 첫 값을 임시 변수에 보관한 뒤 두 저장 위치의 값을 교환합니다.
최대공약수는 (left, right)를 (right, left % right)로 바꾸다가 right가 0이 되면 left를 반환합니다.
입력을 양수로 제한하면 음수 절댓값과 정수 최소값의 경계 문제를 이 문제에서 분리할 수 있습니다.
정답은 재귀 대신 while을 사용하여 호출 스택이 쌓이지 않도록 구현했습니다.

전체 코드는 [ExerciseSolutions.cs](ExerciseSolutions.cs)에 있습니다.

```powershell
dotnet run --project chapters/08-Methods -- --answers
```

정답 실행 출력은 다음과 같습니다.

```text
최댓값: 8
교환: 20, 10
최대공약수: 6
```

</details>

## 복습 질문

### 1. ref와 out의 가장 중요한 차이는 무엇인가요?

<details>
<summary>정답</summary>

ref는 호출 전에 초기화한 변수를 읽고 수정하는 데 사용합니다.
out은 미리 초기화하지 않아도 되지만 메서드가 정상 반환 전에 반드시 값을 대입해야 합니다.

</details>

### 2. 이름과 매개변수 타입이 같고 반환 타입만 다른 메서드를 만들 수 있나요?

<details>
<summary>정답</summary>

반환 타입만 다른 오버로드는 만들 수 없습니다.
매개변수 개수나 타입처럼 호출을 구별할 수 있는 차이가 필요합니다.

</details>

### 3. 재귀에 종료 조건만 있으면 항상 안전한가요?

<details>
<summary>정답</summary>

아닙니다. 실제로 종료 조건에 가까워져야 하고 호출 깊이와 숫자 범위도 고려해야 합니다.
예제는 입력을 0~20으로 제한하고 checked 연산을 사용합니다.

</details>
