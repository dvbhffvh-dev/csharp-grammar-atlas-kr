# 4주 학습 계획

[전체 목차](../README.md)

일정은 하루 40~60분을 기준으로 한 제안입니다. 한 단원의 문제를 스스로 설명하지 못했다면 속도를 늦추세요.
이미 배운 내용은 읽는 시간을 줄이고 문제와 디버깅에 시간을 배분할 수 있습니다.

| 주차 | 학습 | 주말 복습 |
|---|---|---|
| 1주 | 01~06: 구조, 변수, 연산, 문자열, 조건, 반복 | 입력받은 숫자가 짝수인지 검사하고 합계를 구하기 |
| 2주 | 07~12: 배열, 메서드, 값/참조, 클래스, 상속, 인터페이스 | 학생 객체와 평균 계산 메서드를 직접 만들기 |
| 3주 | 13~18: 제네릭, 컬렉션, 예외, null, 람다, 이벤트 | 입력 검증이 있는 목록을 만들고 변경 이벤트 알리기 |
| 4주 | 19~24: LINQ, 레코드, 파일, 비동기, 확장 문법 | 성적 관리 프로젝트 분석 후 기능 하나 추가하기 |

## 매일 남길 기록

다음 네 문장을 자신의 말로 채워 보세요.

```text
오늘 해결한 문제:
이 문법이 필요했던 이유:
실행 전에 예상한 결과와 실제 결과의 차이:
내가 바꾼 입력 또는 조건과 그 결과:
```

단순히 코드를 다시 타이핑하는 것은 첫 단계입니다.
이름·숫자·조건을 바꾸었을 때 어디까지 영향이 퍼지는지 설명하면 이해 여부를 더 잘 알 수 있습니다.

## 다음 단계로 넘어갈 기준

### 1부를 마친 뒤

- `7 / 2`와 `7 / 2.0`이 다른 이유를 설명할 수 있다.
- 반복문이 몇 번 실행되는지 손으로 따라갈 수 있다.
- 배열의 마지막 유효 인덱스와 길이의 차이를 설명할 수 있다.
- `TryParse` 실패 시 사용할 흐름을 만들 수 있다.

### 2부를 마친 뒤

- 변수 복사와 객체 복제를 구분할 수 있다.
- 프로퍼티에서 잘못된 값을 막아야 하는 이유를 설명할 수 있다.
- 상속과 합성 중 어느 쪽이 더 자연스러운지 예를 들 수 있다.
- 빈 목록, 없는 키, `null`, 예외를 각각 다른 상황으로 처리할 수 있다.

### 3부를 마친 뒤

- LINQ 쿼리 작성 시점과 순회 시점을 구분할 수 있다.
- `async`가 자동으로 새 스레드를 만들지 않는다는 것을 설명할 수 있다.
- 파일 읽기와 JSON 변환 중 어디서 실패했는지 구분할 수 있다.
- 레코드 `with`가 내부 참조 객체까지 깊게 복사하지 않는다는 것을 설명할 수 있다.

## 복습 문제를 만드는 법

정상 입력만 반복하지 말고 경계와 실패를 추가하세요.
점수 프로그램이라면 0, 100, -1, 101, 숫자가 아닌 문자, 빈 입력을 시도합니다.
목록 프로그램이라면 항목 0개, 1개, 중복 이름, 없는 이름을 시도합니다.
비동기 코드는 성공뿐 아니라 취소와 예외가 호출자에게 어떻게 전달되는지 확인합니다.

## 종합 프로젝트 확장 순서

1. 학생의 이름 변경 기능을 추가하되 중복을 막습니다.
2. 학생마다 여러 과목 점수를 저장하도록 모델을 바꿉니다.
3. 과목별 평균을 LINQ로 계산합니다.
4. JSON 파일 형식이 바뀔 때 이전 파일을 어떻게 읽을지 정합니다.
5. UI를 추가하고 싶다면 콘솔 입출력과 핵심 계산이 분리되어 있는지 먼저 확인합니다.

기능 하나를 추가할 때마다 정상 입력, 경계값, 실패 시 기존 상태 보존을 확인하세요.
