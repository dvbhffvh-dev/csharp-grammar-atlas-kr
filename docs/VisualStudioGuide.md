## 솔루션과 프로젝트의 차이

솔루션(`.sln`)은 여러 프로젝트를 묶어 보여 주는 작업 단위입니다.
프로젝트(`.csproj`)는 어떤 파일을 어떤 설정으로 컴파일할지 정의합니다.
이 저장소는 단원별 콘솔 프로젝트 24개와 종합 프로젝트 하나로 구성됩니다.
프로젝트가 여러 개 있어도 **실행할 프로젝트는 직접 선택**합니다.

1. Visual Studio의 **파일 → 열기 → 프로젝트/솔루션**을 선택합니다.
2. 저장소 루트의 `CSharpGrammarAtlas.sln`을 엽니다.
3. 솔루션 탐색기에서 `Chapter01`을 오른쪽 클릭합니다.
4. **시작 프로젝트로 설정**을 선택합니다.
5. `Program.cs`를 열고 `Ctrl + F5`를 누릅니다.

다른 단원을 실행하려면 그 프로젝트를 시작 프로젝트로 바꾸세요.
`Program.cs` 탭만 바꾸는 것으로 시작 프로젝트가 바뀌지는 않습니다.

## 예제 파일 읽는 순서

| 파일 | 역할 |
|---|---|
| `README.md` | 개념, 코드 해설, 실행 결과, 실수, 문제 |
| `Program.cs` | 기본 예제와 실행 흐름 |
| `ExerciseSolutions.cs` | 연습문제의 실제 해설 코드 |
| `expected-output.txt` | 수정 전 기본 예제의 예상 출력 |
| `ChapterNN.csproj` | 콘솔 실행 프로젝트 설정 |

`Directory.Build.props`는 상위 폴더의 공통 설정입니다.
따라서 한 단원 폴더만 따로 복사하면 대상 프레임워크 설정이 빠질 수 있습니다.
전체 저장소를 복제하거나, 별도 프로젝트에 코드를 옮길 때 필요한 설정을 직접 지정하세요.

## 중단점으로 한 줄씩 따라가기

08장 `Program.cs`에서 메서드를 호출하는 실행 문장을 찾아 보세요.

1. 해당 줄의 왼쪽 여백을 클릭하거나 `F9`를 눌러 중단점을 만듭니다.
2. `F5`로 디버깅을 시작합니다.
3. 노란 실행 표시가 멈추면 변수에 마우스를 올려 값을 확인합니다.
4. `F10`으로 다음 문장까지 진행합니다. 메서드 호출은 실행하되 내부로 들어가지는 않습니다.
5. 같은 호출에서 `F11`을 누르면 디버깅 가능한 메서드 내부로 들어갑니다.
6. `Shift + F11`로 현재 메서드를 빠져나옵니다.
7. `F5`로 다음 중단점까지 계속 실행합니다. `Shift + F5`로 디버깅을 종료합니다.

문제의 원인을 추측하기보다 **예상한 값과 실제 값이 처음 달라지는 문장**을 찾는 것이 목적입니다.
반복문은 인덱스와 누적 합계를, 객체 예제는 두 변수가 같은 객체를 가리키는지 관찰하세요.
표시되는 줄과 실제 정지 위치는 최적화와 디버깅 정보에 영향을 받을 수 있어 학습 중에는 Debug 구성을 권장합니다.
단축키는 키보드 설정에 따라 달라질 수 있습니다.

## 연습문제 해설 실행

가장 단순한 방법은 저장소 루트에서 다음을 실행하는 것입니다.

```powershell
dotnet run --project chapters/08-Methods/Chapter08.csproj -- --answers
```

Visual Studio 안에서는 해당 프로젝트의 **속성 → 디버그 → 디버그 시작 프로필 UI**를 열고
명령줄 인수에 `--answers`를 입력합니다. 표시 이름은 설치된 언어와 버전에 따라 조금 다를 수 있습니다.
다시 본문 예제를 실행하려면 인수를 비웁니다.

성적 관리에서 직접 입력하려면 `--interactive`, 자체 검증을 실행하려면 `--self-test`를 사용합니다.

## 자주 만나는 오류

### 실행했는데 다른 단원의 결과가 나와요

열려 있는 소스 탭이 아니라 시작 프로젝트가 실행됩니다.
솔루션 탐색기의 시작 프로젝트 표시를 확인하고 바꿉니다.

### SDK를 찾을 수 없다고 나와요

터미널에서 `dotnet --list-sdks`를 실행하여 **10.0.xxx SDK**가 있는지 확인합니다.
런타임만 설치되어 있으면 프로그램 실행은 가능해도 소스 빌드는 할 수 없습니다.
`global.json`은 재현 가능한 학습을 위해 10.0 계열 SDK를 선택합니다.
Visual Studio Installer에서 .NET 개발 구성을 확인하고, SDK와 호환되는 Visual Studio를 사용합니다.

### nullable 경고가 빌드 오류로 보여요

이 저장소는 경고를 오류로 처리합니다. 경고를 숨기는 대신 값이 없을 때의 처리를 작성해 보는 설정입니다.
예를 들어 `Console.ReadLine()`의 반환형은 `string?`이므로 `null` 가능성을 확인해야 합니다.
16장의 `??`, `is null`, 널 흐름 분석을 참고하세요. `!`를 붙이는 것은 런타임 검사가 아닙니다.

### 한글이 깨져요

소스 파일을 UTF-8로 저장하고 터미널의 글꼴과 문자 인코딩을 확인합니다.
예제의 출력 문자열이 깨진 것인지, 파일 내용 자체가 깨진 것인지 구분하세요.
프로그램에는 필요한 경우 `Console.OutputEncoding = System.Text.Encoding.UTF8;`을 추가할 수 있습니다.

### NuGet 패키지를 추가했더니 찾지 못해요

기본 예제는 외부 패키지가 필요 없어 `NuGet.Config`의 공급원을 비워 두었습니다.
새 라이브러리를 실습하려면 해당 설정에 필요한 공식 패키지 공급원을 명시적으로 추가해야 합니다.
이 저장소의 원본 예제를 실행하기 위해 패키지를 설치할 필요는 없습니다.
