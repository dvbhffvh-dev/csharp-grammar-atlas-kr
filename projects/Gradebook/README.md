# 종합 실습 · 성적 관리 프로그램

[전체 목차](../../README.md) · [24장](../../chapters/24-ModernCSharp/README.md)

## 무엇을 만들까요?

학생 이름과 점수를 등록하고, 점수순 목록·평균·등급을 확인하는 콘솔 프로그램입니다.
검색과 삭제를 할 수 있고 JSON 파일에 저장한 데이터를 다시 읽을 수 있습니다.
복잡한 프레임워크 없이 C# 문법이 실제 프로그램 안에서 연결되는 과정을 살펴봅니다.

실제 개인 정보가 필요하지 않은 학습 예제입니다. 예제용 이름으로 실습하세요.

## 권장 선수 단원

- 05~08장: 분기, 반복, 메서드
- 10, 14~16장: 클래스, 컬렉션, 예외, null 처리
- 19~22장: LINQ, 레코드, JSON, 비동기

처음에는 기본 데모만 읽고, 파일 저장과 비동기는 관련 단원을 마친 뒤 따라가도 됩니다.

## 실행하기

저장소 루트에서 실행합니다.

```powershell
dotnet run --project projects/Gradebook/Gradebook.csproj
dotnet run --project projects/Gradebook/Gradebook.csproj -- --interactive
dotnet run --project projects/Gradebook/Gradebook.csproj -- --self-test
```

| 모드 | 목적 | 파일 기록 |
|---|---|---|
| 기본 | 정해진 데이터로 흐름 확인 | 없음 |
| `--interactive` | 직접 메뉴와 값을 입력 | 메뉴 5에서 저장 |
| `--self-test` | 핵심 동작 검증 | 고유 임시 폴더 사용 후 정리 |

기본 데모의 출력은 다음과 같습니다.

```text
학생 3명
지우: 96점 (A)
서연: 90점 (A)
민수: 82점 (B)
평균: 89.33
90점 이상: 2명
검색 '민': 민수
직접 입력하려면 --interactive 옵션을 사용하세요.
```

## 1. 데이터 모델

```csharp
public sealed record StudentScore(string Name, int Score);
```

레코드는 학생 이름과 점수를 하나의 값처럼 묶고, 같은 데이터인지 비교하기 쉽게 해 줍니다.
위 선언으로 생성자와 프로퍼티 등이 만들어집니다. `sealed`는 이 형식의 상속을 막습니다.
이 모델의 멤버는 문자열과 정수여서 내부에 가변 목록을 공유하는 문제가 없습니다.
레코드를 쓴다고 모든 모델이 깊은 불변성을 얻는 것은 아니라는 점은 20장에서 확인합니다.

## 2. 잘못된 데이터가 들어오는 지점을 막기

추가할 때 이름을 `Trim()`하여 앞뒤 공백을 제거하고, 이름이 비어 있거나 점수가 0~100 범위를 벗어나면 예외를 발생시킵니다.
같은 이름의 학생은 이 예제에서 한 명만 허용합니다. 실제 서비스라면 이름 대신 고유 ID로 구분하는 편이 적절합니다.

콘솔에서는 `TryParse`로 숫자 입력을 확인합니다. 서비스는 점수 범위를 다시 확인합니다.
이는 중복 검사가 아니라 책임이 다릅니다. 콘솔은 “숫자로 바꿀 수 있는 입력인가”, 서비스는 “허용되는 점수인가”를 확인합니다.
나중에 콘솔을 거치지 않고 서비스를 호출해도 규칙이 유지됩니다.

## 3. 내부 목록과 외부 결과 분리

```csharp
public StudentScore[] Ranked() => students
    .OrderByDescending(x => x.Score)
    .ThenBy(x => x.Name, StringComparer.Ordinal)
    .ToArray();
```

점수는 내림차순, 동점이면 이름의 ordinal 순서로 정렬합니다.
ordinal은 문화권별 사전 정렬과 같은 개념이 아닙니다. 실행 환경에 따른 순서 차이를 줄이기 위한 선택입니다.
`ToArray()`로 결과를 구체화하기 때문에 호출자가 내부 `List`에 직접 학생을 추가하거나 삭제할 수 없습니다.
이 예제의 레코드 데이터도 일반적인 사용에서 수정되지 않으므로 조회 결과를 전달하기 편리합니다.

## 4. 빈 목록의 평균은 왜 null인가요?

```csharp
public double? Average => students.Count == 0 ? null : students.Average(x => x.Score);
```

학생이 없을 때 평균 0을 돌려주면 “0점을 받은 학생들”과 “학생이 없음”을 구분하기 어렵습니다.
`double?`로 데이터가 없는 상태를 표현하고 UI에서 `평균: 데이터 없음`을 출력합니다.
빈 시퀀스에 대한 `Average` 예외도 호출 전에 막습니다.

## 5. 파일 저장과 불러오기

저장 경로는 실행 시 작업 폴더 아래 `data/students.json`입니다. 대화형 모드 시작 시 실제 경로가 표시됩니다.
Visual Studio와 터미널의 작업 폴더는 다를 수 있으므로 저장된 파일을 찾을 때 표시된 경로를 확인하세요.

저장할 때는 임시 파일에 JSON을 모두 기록한 뒤 목적 경로로 이동합니다.
이렇게 하면 직렬화 도중 실패했을 때 기존 파일을 먼저 비우는 일을 피할 수 있습니다.
이 예제는 동시에 여러 프로세스가 편집하는 상황이나 전원 장애까지 처리하는 데이터베이스가 아닙니다.

불러올 때는 역직렬화한 목록의 모든 항목을 먼저 검사합니다.
유효한 목록이라는 것이 확인된 다음에만 기존 `students`를 바꿉니다.
중간 항목 하나가 잘못되어도 기존 목록은 유지됩니다. 메뉴 6에서 `y`로 확인해야 교체합니다.

`await using`은 비동기 파일 작업 뒤 스트림을 정리합니다.
`await`는 작업이 끝난 뒤 다음 단계로 진행하게 하면서 미완료 I/O를 기다릴 때 호출 스레드를 점유하지 않을 수 있게 합니다.

## 대화형 모드 실습 순서

1. 메뉴 1에서 `가람`, `95`를 입력합니다.
2. 메뉴 1에서 `나래`, `70`을 입력합니다.
3. 메뉴 2에서 점수순 목록과 평균 `82.50`을 확인합니다.
4. 같은 이름 `가람`을 추가해 중복이 거부되는지 확인합니다.
5. 메뉴 5로 저장합니다.
6. 메뉴 4에서 `가람`을 삭제하고 목록을 확인합니다.
7. 메뉴 6에서 `y`를 입력하여 저장한 목록으로 돌아가는지 확인합니다.
8. 메뉴 0으로 끝냅니다. 저장하지 않은 변경은 다음 실행에 남지 않습니다.

### 문제 2 · 점수 수정

학생 이름으로 점수를 바꾸는 `UpdateScore`를 추가하세요. 없는 이름이면 성공/실패를 구분할 수 있게 하세요.

<details>
<summary>구현 방향</summary>

있으면 `students[index] = students[index] with { Score = newScore };`로 레코드를 교체합니다.

`IGradebookRepository`를 만들어 JSON 저장을 분리하고, 테스트에서는 메모리 구현을 주입해 보세요.

<details>
<summary>설계 방향</summary>

서비스에는 입력 검증과 점수 계산을 남깁니다. 저장 실패가 서비스의 목록 상태를 바꾸지 않는지 확인합니다.

</details>

## 자체 검증의 의미

`--self-test`는 빈 평균, 입력 범위, 중복 이름, 등급 경계, 검색/삭제, JSON 왕복,
잘못된 파일·중복 파일을 읽었을 때의 기존 데이터 보존을 검사합니다.
모두 통과하면 `Gradebook self-tests: PASS`를 출력합니다.
실제 프로젝트에서는 전용 테스트 프레임워크로 분리할 수 있지만, 이 학습 자료는 추가 패키지 없이 실행하도록 구성했습니다.
